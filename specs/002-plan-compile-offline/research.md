**Feature**: `specs/002-plan-compile-offline` · **Date**: 2026-08-07

## R1 — Which routing engine, reached how? (NEW → ADR-0020)

- **Decision**: **Valhalla** (MIT, official `ghcr.io/valhalla/valhalla-scripted` image), graph built **per area at compile time**, reached over HTTP behind a `RoutingProvider` protocol in `commons/routing.py`. Exactly **two endpoints**: `POST /route` with `costing:"pedestrian"` for leg geometry + duration (`RouteLegV1`), and `POST /sources_to_targets` (the matrix service) for the N×N feasibility time matrix — one call per feasibility re-check. Costing options are fixed and explicit: `{"pedestrian": {"walking_speed": <pace>, "walkway_factor": 0.9}}`, where `walking_speed` comes from the user's pace preference (**3.5–5.0 km/h**; Valhalla accepts 0.5–25 and **defaults to 5.1 km/h**, which is brisk for a sightseeing day and changes feasibility verdicts more than engine choice does). Three implementations behind the protocol: `ValhallaProvider` (Tier 2 + prod), `OpenRouteServiceProvider` (zero-infra dev fallback, free key ≈2,500 req/day), `FixtureProvider` (recorded responses, Tier 1, no network).
- **Tile-build trigger**: compile-time, keyed `(area_id, pbf_date)`. The container builds tiles on first start from a mounted per-area PBF extract (~1–5 min); the built tile directory lives in a named docker volume, so recompiling the same area is a no-op. Compile blocks on Valhalla's `/status` readiness, never on a sleep.
- **How CI avoids paying for a graph build**: job 1 (Tier 1) never touches Valhalla — `FixtureProvider` replays committed JSON recorded once against a real container, sitting beside the existing Overture parquet fixture. The real container runs **only** in job 3 behind the `integration` marker, against a **tiny committed old-town PBF** (single-digit MB → seconds, not minutes), with the tile directory cached across runs keyed on the PBF hash. No PR ever builds a metro graph.
- **Rationale**: stack reference §5 already ranks Valhalla first — MIT, best-in-class pedestrian costing, and route + matrix + optimized-order from one box. Its data is OSM → the legs are an ODbL Produced Work (`DATA-LICENSES.md`, Valhalla row), which the ATTRIBUTION pipeline already knows how to discharge.
- **Alternatives rejected**: OSRM demo server (its own policy says not for production; access withdrawable); GraphHopper hosted (free tier ≈500 credits/day, too small); ORS as *primary* (GPL-3.0 backend + daily quota + a live external dependency inside the compile path — fine as the dev fallback, wrong as the engine of record); straight-line haversine (FR-003 forbids presenting it as a route).
- **Confirmation**: `tests/test_routing_provider.py` (Tier 1, fixture provider — protocol conformance, asserts no socket is opened); `tests/test_compiler_routes.py` under `-m integration` against the real container, asserting leg distance/duration agree with the recorded fixture within tolerance; and a **seam-purity tripwire** mirroring `tests/test_llm_seam.py` — no HTTP call to a routing host may appear outside `commons/routing.py`.

## R2 — Where do the tiles come from, and how big is a day? (NEW → ADR-0021)

- **Decision**: `pmtiles extract` (go-pmtiles CLI) against the **Protomaps daily build**, `--bbox` = itinerary extent + buffer, `--maxzoom=15`, keeping the full **z0→15** sub-pyramid (partial-zoom extracts are inefficient; clustered source required, which Protomaps builds are).
- **Build-URL resolution at run time**: never hardcoded, never hotlinked from a client. Protomaps' own docs say *"URLs may change and hotlinking to these downloads are discouraged"* and retain **builds for the past week**. `compiler/tiles.py` lifts the resolver already proven in `scripts/fetch-basemap.sh`: HEAD `https://build.protomaps.com/<YYYYMMDD>.pmtiles` walking back from today up to 7 days, take the first that answers, record the resolved date as `TileSourceV1.build_date`, and **fail loudly** if none answers. Protomaps' recommended "copy the tileset to your own Cloud Storage" is the M2 mirror once compile volume justifies it.
- **Buffer = 1 km** geodesic around the union of stop points and leg geometries, then the bbox of that, with a **minimum bbox span of 2 km**. FR-016 asks for "a margin sufficient for a traveller who strays, and no more". An earlier draft of this section said 500 m; that was overridden on 2026-08-07 once the extract was measured at **~1.3 MB against a 200 MB budget** — the tighter number bought nothing real, 500 m is only ≈6 min of straying at a sightseeing pace (thin for the FR-019 recovery promise), and a compact single-block day can produce a bbox smaller than the map viewport. The minimum span exists for that last case. Computed with **shapely 2.x** (`unary_union` over the leg `LineString`s + stop points, buffered in a local projected CRS, envelope reprojected back to **EPSG:4326**) — never a naive degree offset, which is anisotropic away from the equator.
- **maxzoom = 15** because that is the Protomaps build ceiling, not a budget choice. Each zoom ≈ 2× size, so `--maxzoom=14` is the documented lever if a metro day ever breaches ≤200 MB; M1 holds z15 for old-town legibility at walking scale.
- **Size estimate — from this repo's own measurement, not a rule of thumb**: `scripts/fetch-basemap.sh` extracts the Rhodes window `28.20,36.42,28.25,36.46` (≈4.5 × 4.4 km) at z0–15 to **~1.3 MB**, plus ~1.5 MB of glyphs and sprites. A compact old-town day is therefore **single-digit MB** — two orders of magnitude inside SC-007's ≤200 MB. (The stack reference's 10–40 MB figure is a conservative 5×5 km rule of thumb; the measured extract is the better number.) The size budget is not the binding constraint at M1.
- **Carried-forward gap, flagged not solved here**: the dev script prunes glyph ranges to U+0000–U+04FF. The *compiled* bundle must select ranges from the **area's own label scripts**, or SC-009 (genericity against a second area of different character) fails silently on a Hebrew/Arabic/CJK area — labels render as nothing. This is a DU-05 compile requirement.
- **Alternatives rejected**: Planetiler self-build (Java + per-area PBF + OpenMapTiles schema binds the style family — kept as the sovereignty fallback and the route to a baked POI layer, M2+); hosted Protomaps API tiles (needs network at travel time — disqualified by Article I); pinning one build URL (discouraged upstream, and retention is ~1 week).
- **Confirmation**: `tests/test_compiler_tiles.py` — resolver selects a build inside the retention window and raises when none answers; buffer asserted against a known metric distance (projected, not degrees); `TileSourceV1` fields validate against `docs/data/tile-source.md`. Tier 2 compile contract test asserts the demo-day bundle is **< 20 MB** total.

## R3 — How are OSM `opening_hours` evaluated from Python? (NEW → ADR-0022) *(the genuinely open one)*

Candidates investigated 2026-08-07:

| Candidate | Real name | License | Maintenance | PH / SH | Interval evaluation |
|---|---|---|---|---|---|
| Rust-backed binding | **`opening-hours-py`** (PyPI dist `opening_hours_py`; import `from opening_hours import OpeningHours`) — bindings over the Rust crate `opening-hours`, [remi-dupre/opening-hours-rs](https://github.com/remi-dupre/opening-hours-rs) | **MIT OR Apache-2.0** (both in the bundleable set) | **2.1.4, released 2026-07-07** — active | **PH yes** (embedded nager.Date holiday DB, country-scoped). **SH: not documented as supported** | Yes — `state()`, `next_change()`, lazy infinite interval iterator, `ZoneInfo` or coordinate-inferred timezone, sun events |
| Canonical JS | `opening_hours.js` v3.9 | **LGPL-3.0** | Active; the reference implementation | **PH and SH**, with `nominatim_object` locale | Yes — the most complete evaluator that exists |
| JS wrapper | `pyopening_hours` ([opening-hours/pyopening_hours](https://github.com/opening-hours/pyopening_hours)) — bridges to `opening_hours.js` | **GPL-3.0** — *not* in the bundleable allowlist, and copyleft over `commons/` | **Dead: PyPI 0.3.0, last upload 2015-10-09** | via the JS lib | via the JS lib |
| Humanizer | `osm-humanized-opening-hours` / `osm-opening-hours-humanized` | AGPL / varies | Its own README asks for new maintainers | not verified | **No — it renders human-readable descriptions, it does not evaluate** |
| ⚠️ **Name trap** | `opening-hours` (import `opening_hours`, `anthill/Python_OpeningHours`) — **what `pip install opening-hours` actually resolves to** | **UNKNOWN** | abandoned at **v0.1.1** | — | — |

**The install name matters**: the distribution is **`opening-hours-py`** (PyPI metadata name `opening_hours_py`), which imports as `opening_hours`. `pip install opening-hours` silently installs the abandoned, unlicensed 2015 package instead — worth an explicit case in the job-6 slopsquatting gate.

- **Decision**: `commons/opening_hours.py` wraps **`opening-hours-py`** (resolved-then-pinned at implementation; observed 2.1.4) as the single deterministic evaluator, called with the area's timezone and country code. It **fails closed**, three ways: (a) an expression the library refuses to parse is never guessed — the stop is marked `hours_unknown`, which blocks a silent feasibility pass and surfaces as a named conflict per FR-005; (b) `SH`-bearing expressions, and any form the parser rejects, are **rejected loudly with the raw string shown**, never approximated; (c) `PH` is trusted only where the area's country is in the embedded holiday database — elsewhere PH-bearing rules degrade to `hours_unknown`, never to "open". Documented library limit carried through: expressions evaluate as closed before 1900 and after 9999.
- **The honest scope statement, stated as the ADR will state it**: **M1 supports the subset `opening-hours-py` parses, plus PH where the country is covered; everything else is a named infeasibility, not a guess.** Partial support that fails closed is the posture; a silent wrong answer is the failure SC-002 exists to prevent.
- **Rationale**: this replaces an LGPL-3.0 JavaScript dependency with a permissively-licensed, actively-maintained, Rust-backed **Python** one — no second runtime in compile or CI, no LGPL obligation, and the evaluation stays where FR-004 requires it: deterministic machinery, **never the LLM**.
- **Registry consequence — flagged, not done here** (single-file ownership): `DATA-LICENSES.md` registers `opening_hours.js` / LGPL-3.0 as the feasibility evaluator, and `docs/data/poi-site.md` + `docs/data/itinerary.md` name it in prose. If ADR-0022 is accepted, those become `opening-hours-py` / MIT OR Apache-2.0 and the LGPL row disappears — a **reduction** in obligation. **DU-04 task.** Note also that **`opening_hours_js` is a live `SourceKind` enum value** in `commons/licenses.py` (and carries a trust weight in `commons/merge.py`), not just prose. **Keep the enum value** — renaming it is a `SiteRecordV2` concern — and have ADR-0022 record that it now means "deterministic opening-hours evaluation", whatever engine backs it.
- **Alternatives rejected**: embedding `opening_hours.js` via a JS runtime (Node subprocess / QuickJS binding) — a whole second runtime in every compile and CI job, plus LGPL unmodified-dependency discipline, to buy SH support the demo day does not need; a hand-rolled subset parser (re-deriving a messy grammar is exactly how silent wrong answers happen); Overture's operating-status field as the evaluator (coverage still uneven per stack reference §4 — useful as a cross-check signal, not as the source of truth); the LLM (forbidden, FR-004).
- **Confirmation**: `tests/test_opening_hours.py` — a table of real OSM strings from the Rhodes fixture with expected open/closed at **fixed instants under a frozen clock**, no network; plus an explicit **rejection table** asserting `SH`-bearing and unparseable strings raise and surface as `hours_unknown` rather than defaulting open. `evals/test_structural.py` gains the SC-002 assertion that no itinerary is approvable with an unresolved hours conflict. A one-off Tier 2 differential run against `opening_hours.js` in a Node container sizes the divergence and is recorded **as evidence in the ADR**, not run per PR.

## R4 — How does the persisted HITL pause work? (NEW → ADR-0023)

- **Decision**: ADR-0004 replaced LangGraph's `interrupt()` with an owned Postgres checkpoint (one `UPSERT` per step over the `user_plan` row), so the pause is a **row state, not a suspended coroutine** — which is precisely why it survives a restart: there is nothing in memory to lose. `user_plan` carries `status ∈ {proposing, proposed, approved, superseded, compiling, compiled, failed}`, `revision int`, `approved_at`, `approved_by`, and `itinerary_hash` (SHA-256 over the canonical `ItineraryV1` JSON), row-scoped to the auth subject (FR-007). **The pause is `status='proposed'`.** Compile selects only `status='approved'` and flips `approved → compiling` **in the same transaction**, so the gate is a database constraint, not an application check anyone can forget.
- **State machine**: `proposing → proposed` (planner writes the proposal) · `proposed --approve--> approved`, permitted **only** when feasibility passes (FR-005) · `proposed|approved --edit--> proposing` at `revision+1`, with the prior row set `superseded` — which is the spec's "plan edited after approval returns it to unapproved and re-runs feasibility".
- **Double approve** resolves to one outcome by **compare-and-set**: `UPDATE user_plan SET status='approved' … WHERE plan_id=:id AND status='proposed' AND itinerary_hash=:hash`. The first approve updates one row; the second updates **zero** and returns the existing approval — an idempotent 200 with the same `approval_id`. Never two approvals, never two bundles, never an error the user has to interpret.
- **Stale approve** (user approves revision 3 while revision 4 exists): the hash predicate fails, zero rows update, and the response is a **409 naming the current revision** — deliberately the same idiom as ADR-0016's process-local 409 research guard, so the API has one concurrency shape rather than two.
- **Alternatives rejected**: an in-memory `asyncio.Event` pause (loses the decision on a bounce — the exact thing FR-006 forbids); LangGraph `interrupt()` + checkpointer (excluded by ADR-0004); an append-only approvals table with last-write-wins (two approvals become two rows, then two divergent bundles); optimistic locking on `updated_at` instead of a content hash (a no-op re-save would falsely invalidate a live approval).
- **Confirmation**: `tests/test_hitl_gate.py` — (a) compile refuses a `proposed` plan; (b) an approval survives a **process restart** between propose and approve (SC-003 = 100%); (c) concurrent double-approve yields exactly one `approval_id`; (d) editing an approved plan returns it to `proposing` and re-runs feasibility before compile is permitted. (b) and (c) run under `-m integration` against real Postgres — the guarantee is the transaction's, not the ORM's.

## R5 — Where does narration come from, and what does share-alike oblige? (NEW → ADR-0024)

- **Decision**: **MediaWiki Action API** over **Wikivoyage** (listing templates + prose) and **Wikipedia** (`list=geosearch` + summary extracts), with an honest descriptive User-Agent and results cached in the commons. Both are **CC BY-SA 4.0**. Wikitext is parsed with `mwparserfromhell` (stack reference §4 prefers this over scraping rendered HTML — the listing templates are the structured prize) — resolved-then-pinned. `commons/sources/wikivoyage.py` is a source adapter exactly like the Overture and Overpass ones: it **stamps at the boundary**, so nothing above it is ever unstamped.
- **Attribution captured at ingestion**, per article, per revision, into the `SourceRef`: `{kind: "wikivoyage"|"wikipedia", id: "<lang>:<Page Title>", url: <canonical article URL>, license: "CC-BY-SA-4.0", attribution: "\"<Title>\", <Wikivoyage|Wikipedia>, <url> — authors via page history", observed_at: <revision timestamp>, bundleable: true}`. The **`revid`** is fetched with the extract and stored, so the credit points at the exact revision adapted — Wikimedia's reuse guidance accepts a link to the article/history as author attribution, and the revid is what makes that link honest. Both `kind` values already exist in the `SourceRef.kind` enum (`docs/data/poi-site.md`) — **no schema change**.
- **Share-alike, stated explicitly**: adapted prose from a CC BY-SA 4.0 article is a **derivative work**, therefore **the bundled story text is itself CC BY-SA 4.0 and the bundle must say so**. The obligation is viral **over the text only** — it does not reach the app code, the MapLibre style, the tiles, or the itinerary data. Discharge is mechanical: `ATTRIBUTION.md` gains a `Narration text: CC BY-SA 4.0 — adapted from:` block listing every contributing article by title + URL, and the manifest carries `textLicense: "CC-BY-SA-4.0"`. This is PRD §7 posture (a), already a standing decision — ADR-0024 **records** the obligation, it does not re-open the posture.
- A story with no `SourceRef` is refused by the same quarantine filter as any other unstamped value (FR-012); a place with no available article carries **no** story and nothing is invented (FR-023). Wikidata (**CC0**) remains the preferred machine-*facts* source and is not a narration source.
- **Alternatives rejected**: Wikimedia Enterprise Travel API (commercial; the free APIs are ample at slice volume); scraping rendered HTML (brittle, and discards the listing-template structure); open-web prose (always `bundleable=false`); facts-only narration from Wikidata alone (PRD §7 posture (b) — rejected by the standing decision, and a thinner product).
- **Confirmation**: `evals/test_structural.py` extended — every bundled `Story` has a non-null `SourceRef` with `license == "CC-BY-SA-4.0"` and a resolvable article URL (**SC-010 = zero stories without attribution**); `tests/test_compiler_attribution.py` asserts the generated `ATTRIBUTION.md` names every contributing article exactly once and declares the text license; the existing quarantine invariant now also sees story text.

## R6 — How does the Playwright harness assert *zero* network requests?

- **Decision**: **both mechanisms, layered**, because they answer different questions. `context.setOffline(true)` proves the app *works* with no network; a catch-all **`context.route('**/*', …)` recorder** proves it *makes no request at all*. Under `setOffline` alone an attempted request is invisible unless you also listen for `requestfailed` — and a request served from the SW Cache API never fails, so "it still rendered" can hide a live network dependency. FR-018/SC-005 is **zero requests**, so the assertion must be over requests **observed**, not requests **failed**.
- **Shape**: online phase (load, download bundle into OPFS, wait for the service worker to reach `activated`) → install a context-level route handler that **records every request URL and aborts it** → `context.setOffline(true)` → `page.reload()` → run the travel flow → assert the recorded list is **empty**. **Allowlist nothing.** If some request must ever be allowed, it is named in the ADR, not waved through with a glob.
- **Two Chromium footguns, pre-armed**: (a) `page.on('request')` misses requests issued by the **service worker** and by **workers** — the handler must be installed on the **context** with `serviceWorkers: 'allow'`, and Siyur's OPFS reader is itself a module worker (`worker.format:'es'`, ADR-0003). (b) `data:` and `blob:` URLs are not network — filter by **scheme**, never by host allowlist.
- **Stand it up early** (plan Risk 1): the harness lands at **DU-04**, not DU-06, against the existing DU-00 empty map — load `web/`, go offline, reload, assert zero requests and a present map canvas. DU-05/06 then only *add* assertions (itinerary, timeline, story text, recovery route). CI job 5 stops being an `echo` at DU-04, the earliest point the gate can stop lying.
- **Repo state**: there is **no Playwright in this repo today**. Add `@playwright/test` to `web/devDependencies` (**1.62.1 observed 2026-08-07**; resolved-then-pinned at implementation per ADR-0007) and `pnpm exec playwright install --with-deps chromium` in job 5. **Chromium only** — ADR-0002 makes Chromium the target and WebKit an explicitly flagged future ADR; extra browsers would buy failures we have not decided to care about. `.github/workflows/**` is `ask`-gated (ADR-0006), so the job-5 rewrite is one deliberate, human-approved edit.
- **Alternatives rejected**: `setOffline` alone (cannot distinguish "made no request" from "made a request that was swallowed"); route-abort alone (the browser still believes it is online, so `navigator.onLine`-conditioned code takes the wrong branch and you test the wrong path); driving CDP network emulation directly (lower level, no extra signal); vitest/jsdom (no service worker, no OPFS — it cannot host this gate at all).
- **Confirmation**: **CI job 5 is itself the confirmation** — that is the point of the slice. `web/test/e2e/airplane.spec.ts` asserting `recorded.length === 0`, plus a **negative-control spec** that deliberately requests a remote asset and asserts the harness catches it. A gate that cannot fail is the stub we are replacing.

## Could not verify — carry into implementation

1. **`opening-hours-py` school-holiday data.** The `SH` selector is *syntactically* accepted and public holidays are documented as an embedded per-country database; I found **no evidence of an embedded school-holiday dataset**. The fail-closed posture above already covers this, but verify against the installed wheel at pin time.
2. **No upstream conformance suite exists** between `opening-hours-py` and `opening_hours.js` — neither project publishes a cross-implementation comparison. "Matches the canonical evaluator" is a claim nobody can make; the one-off differential run recorded in ADR-0022 is the only evidence we will have.
3. **Wheel coverage on the CI runner architecture** — PyPI advertises cp310–cp314 wheels across manylinux / macOS-arm64; confirm at pin time, because a source build drags the Rust toolchain into CI.
4. **`ghcr.io/valhalla/valhalla-scripted:latest` is a floating tag** — pin a digest at implementation (ADR-0007); no current digest was verified here.
5. **Protomaps publishes no programmatic "latest build" index or `/latest` redirect** — the 7-day walk-back is our own mechanism, not an upstream contract, and breaks if the URL scheme changes.
6. **ORS free-tier limits** (≈2,500 req/day) are quoted from the stack reference's 2026 pricing digest and were not re-verified against ORS directly.

Ready for Phase 1.
