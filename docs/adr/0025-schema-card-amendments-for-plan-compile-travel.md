# 0025 — Schema-card amendments revealed by the plan/compile/travel design

- Status: proposed
- Decision Maker(s): Ben
- drafted-by: claude-code · approved-by: _pending_ · Date: 2026-08-07

## Context and Problem Statement

`docs/data/*.md` schema cards are **approved design artifacts and field-level ground truth** — `AGENTS.md` says "never guess a schema; read the card", and `specs/002-plan-compile-offline/data-model.md` opens by stating that where it and a card differ, **the card wins**. That rule only works if the card is *right*. Transcribing the cards into the slice-002 data model surfaced twelve places where a card is **silent, ambiguous, self-contradictory, or stale** in a way the implementation cannot route around: `data-model.md` §9 lists them as G1–G12 and, correctly, **patches none of them**.

The cards cannot be left as they are, for a reason specific to this slice. Slice 002 is the first to produce the **bundle** — a frozen artifact handed to a traveller with no connectivity and no way to ask a follow-up question. Every gap below is a place where two reasonable implementations would disagree and the disagreement would show up as a blank screen in airplane mode, an unverifiable hash, or an unrendered legal obligation. FR-013 (per-artifact integrity), FR-017 and FR-021 (everything the traveller depends on resolves to a manifest path) are **structurally unsatisfiable** against the cards as written.

This ADR exists because the alternative — letting the code decide and back-filling the cards afterwards — inverts the repo's own authority rule. A ruling recorded here is a decision Ben ratifies once; a ruling made in a pull request is a decision nobody sees.

## Considered Options

- **A — Rule on every gap now, amend the cards in place, keep `V1`.** One ADR, one ratification, and the cards are corrected before any slice-002 code reads them. Additive fields and corrected examples; nothing already implemented changes meaning.
- **B — Let the implementation decide each gap and back-fill the cards at the slice audit.** How slice 001 handled its *discoveries* (see `poi-site.md`'s T067 audit). But those were rules the code *revealed*; these are contradictions the code would have to *resolve*, silently, twelve times, before any reviewer sees them — and two of them (canonical hashing, per-artifact hashes) are cross-implementation contracts where a silent choice is indistinguishable from a bug until a bundle fails to verify on a device.
- **C — Bump the schemas: `ItineraryV2` / `BundleManifestV2`.** Honest about the scale of the change. But `BundleManifestV1` has never been implemented (the `compiler/` package is empty since DU-00) and `ItineraryV1` has no rows in production, so a version bump would migrate nothing and buy nothing except two names for the same shape.
- **D — Rule only on the load-bearing gaps and leave the rest open.** Tempting for the merely-editorial ones, but the misleading examples (`_feasibility`, `Timeline.stop_id`) are exactly what a transcriber copies; leaving a wrong example in an authoritative card is worse than leaving a silence.

## Decision Outcome

Chosen: **A — rule on all twelve now, amend the cards in place, stay at `V1`.** The schemas are unimplemented or unpopulated, so these are **corrections to a specification before first use**, not migrations of a live contract; every field added is additive and every example fixed was wrong. Rulings are recorded here so the reason survives the edit.

**The rulings.** Each row is binding on the named card(s); nothing outside this table is decided here.

| # | Gap (as found in `data-model.md` §9) | **Ruling** | Card(s) amended |

A group hash cannot say *which* artifact was corrupted, which is what FR-013 asks for. | `bundle-manifest.md` |

**Deliberately not ruled here.** `data-model.md` §9's **G9** (the itinerary card's leg examples omit `geometry` and `source`, both M1-required per `route-leg.md`) and **G12** (no `created_at`/`updated_at` on `ItineraryV1`; no stated `bundle_id` format; `RouteLeg` vs `RouteLegV1` naming; `created_by` on `area` vs `user_id` on `user_note`/`user_plan`) are **editorial or minor**: they need no ruling, and where an amending edit fixes one in passing (completing a leg example, writing `RouteLegV1` for `RouteLeg`) that is a typo correction, not a decision. They are named here so their absence from the table reads as a choice rather than an oversight; anything left unfixed stays open in `data-model.md` §9.

**Scope / non-goals**: this ADR amends **cards**. It does not decide the routing engine (ADR-0020), the tile source (ADR-0021), the opening-hours evaluator (ADR-0022 — ruling 12 only *propagates* it), the HITL mechanism (ADR-0023), or the narration source (ADR-0024). It introduces **no `V2` schema**: every change is additive, a corrected example, or a prose statement of an existing convention.

### Consequences

- **These amend approved design documents.** The cards are not drafts; slice 001 shipped against them and `data-model.md` defers to them. Ratifying this ADR is ratifying twelve edits to approved artifacts, which is why they are listed individually rather than summarised.
- **`docs/design/tech-design.md` §1.3 (`ItineraryV1`) and §1.4 (`BundleManifestV1`) are the upstream authority for these cards.** They therefore need **the same amendments, or an explicit pointer to this ADR**, or the cards will contradict the document they were derived from — reintroducing exactly the ambiguity this ADR closes, one level up. This is a required follow-up, not an optional tidy.
- Good: FR-013, FR-017 and FR-021 become satisfiable. Per-artifact hashes name the corrupted artifact; the frozen itinerary has a path; the withheld list gives the "needs connectivity" affordance something to render.
- Good: canonicalization is a stated contract, so the Python writer and the TypeScript launch-time verifier are testable against each other rather than against each other's assumptions.
- Good: ruling 12 **removes** an LGPL-3.0 obligation from the registry.
- Bad / accepted cost: **ruling 2 requires an Alembic migration** (`area.timezone`, `area.country_code`) — **`ask`-gated, Ben approves** (CLAUDE.md). It also adds a deterministic derivation step at area-resolve time that must work for **any** area (SC-009 genericity), including polygons straddling a timezone or country boundary — the derivation must pick deterministically and record what it picked, never prompt.
- Bad / accepted cost: existing bundle-manifest **examples in the cards are rewritten**, so any external reader who copied them is now wrong. Accepted: no bundle has ever been produced, so nobody has.
- ~~Bad / accepted cost: ruling 3's `user_plan.feasible` + `user_plan.violations` conflicts with `data-model.md` §6…~~ **RESOLVED 2026-08-07 (task T007b).** The conflict was wider than this note recorded — **five** documents disagreed, not two: `data-model.md` §6 (two states, one `feasibility jsonb`), this ruling (two verdict columns), ADR-0023 (seven states), `contracts/plans.md` (three exposed states, plus a `superseded_by` ADR-0023 never defined). Reconciled in `data-model.md` §6, which is now the shape `0005_user_plan` is written from: **ADR-0023's seven states, exposed verbatim by the API with no mapping layer; the verdict as two columns** (`feasible boolean` takes a real `CHECK` and an index where `feasibility->>'ok' = 'true'` is a string comparison against JSON); and `superseded_by` added to ADR-0023's column table. The `CHECK`s are written over the **post-approval set** — `CHECK ((status='approved') = (approved_at IS NOT NULL))` rejects `compiling`/`compiled` rows outright, which is the trap amendment A1 records.
- Bad / accepted cost: ruling 8 leaves a **real asymmetry** in the model — one fact-bearing structure that is not a `SourcedValue`. Documenting it is cheaper than a `SiteRecordV2`, but it is a trap that now depends on the card being read.
- Accepted: `BundleManifestV1` grows (embedded `TileSourceV1`, six per-artifact hashes, `withheld`, the frozen itinerary path, and `textLicense` from **ADR-0024**). A manifest that is longer but wholly resolvable is the point of the airplane-mode contract.

### Confirmation

- **Schema-card round-trip tests (`tests/test_models.py`)**, extended per ruling: every amended card's example rows **construct and re-serialize** against the pydantic model without loss — which is precisely the test that would have caught `_feasibility` (ruling 3) and the site-UUID-as-`stop_id` example (ruling 4), since neither can be built under `extra="forbid"` and the correct addressing.
- **`evals/test_structural.py`** (deterministic, merge-blocking) — the two invariants these rulings exist to make checkable:
  - **manifest integrity**: every per-artifact `sha256` (rulings 5 and 7, including `attribution.sha256`) matches the artifact's bytes, and `integrity.manifest_sha256` recomputes over the **canonical JSON with `integrity` omitted** (ruling 6) — the canonicalization asserted explicitly, so a writer that sorts keys differently fails here rather than on a traveller's device;
  - **every path resolves**: every path named in the manifest exists in the bundle **and** everything the travel UI reads resolves to a manifest path — including the frozen `content.itinerary` (ruling 1), with quarantined content presenting from `withheld` (ruling 9) as "needs connectivity", never as an error or a blank (FR-021).
- **`tests/test_feasibility.py`**: a fixture area whose `timezone`/`country_code` are derived from its polygon (ruling 2) evaluates opening hours under a frozen clock; an area missing either is a **hard failure at resolve time**, not a silent UTC fallback.
- **`tests/test_licenses.py` / the quarantine invariant**: a `Story` with a non-bundleable license is dropped by derivation, not by a stamp (ruling 8), and `DATA-LICENSES.md` no longer contains an LGPL-3.0 row (ruling 12).

## Amendments (2026-08-07, same session — review of the draft above)

Reviewing this ADR against ADR-0023 and `data-model.md` surfaced four things the ruling table left wrong or open. They are recorded here rather than silently edited into the table, because two of them correct a ruling that was already written down.

- **A1 — the obvious `CHECK` for ruling 3 is wrong, and would have shipped.** `CHECK ((status='approved') = (approved_at IS NOT NULL))` — the form specified in `data-model.md` §6 and in this slice's task list — **rejects `compiling` and `compiled` rows**: under ADR-0023's seven-state machine, a plan that is approved and then begins compiling violates its own constraint the moment the state advances. The constraint must be written over the **post-approval set** (`approved_at IS NOT NULL` for `approved`/`compiling`/`compiled`, `NULL` before), and the unapprovable-when-infeasible `CHECK` needs the same treatment. **`tasks.md` T009 carries the corrected form; it must not be written from `data-model.md` §6 as-is.**
- **A2 — ruling 2's derivation rule was under-specified, and this amendment's own first attempt made it worse.** "Derived deterministically from the polygon" had no answer for a polygon straddling a timezone or country boundary, which is ordinary for a cross-border metro. A first version of A2 pinned it to the polygon's `representative_point()`, reasoning that a centroid can fall outside a concave polygon. **That is withdrawn.** The reasoning is sound about *centroids*, which the rule never used, so it fixed a problem that did not exist — and it replaced a rule that picks the zone a polygon *mostly lies in* with one that picks whichever zone happens to contain one sampled point. For a ring 80% in Greece whose sample lands in the Turkish 20%, `opening-hours-py` would then resolve `PH` against the Turkish holiday calendar and every Greek-holiday closure would evaluate as open — the silent wrong answer SC-002 exists to prevent.
  - **Pinned, normative:** resolve to the timezone whose zone polygon has the **largest area of intersection** with the resolved polygon; ties break on the **lexicographically smallest IANA id**. Same rule against country polygons, ties on the lexicographically smallest ISO 3166-1 alpha-2 code. `docs/data/area.md` is the field-level authority and states this.
  - **Permitted optimization:** where the polygon intersects exactly one zone — overwhelmingly the common case for a walkable day — a single point-in-polygon lookup is equivalent and may be used. If one is used, take `representative_point()` and **never the centroid**. The shortcut must agree with the rule wherever both are defined.
  - This also implies an **offline timezone/country boundary-polygon dataset that no ADR previously pinned**; it is a named task (`tasks.md` T008), must work with no network so CI stays reproducible, and — being OSM-derived — is **ODbL and needs a `DATA-LICENSES.md` row**.
- **A3 — ruling 9's `withheld[].reason` is a closed enum, not free text.** `withheld` ships inside an artifact the user downloads. Describing license quarantine is safe; a free-text reason is a channel through which any future withholding rule — including one touching the private side of the PRD §13 #4 boundary — could carry content out in a downloadable file. A closed enum is sufficient to render the "needs connectivity" affordance and cannot carry more than it should. **The members are exactly `license_forbids_redistribution` and `source_unavailable`.** In particular the enum must **not** carry `unstamped` (an earlier draft of this amendment did): FR-012 *refuses* unstamped input — the compile fails — so a value is withheld **or** refused, never both. Giving "unstamped" a withheld reason would turn a merge-blocking refusal into a placeholder indistinguishable from success. Do not source the string from `licenses.quarantine_reason`, which returns free text naming the internal allowlist.
- **A5 — ruling 6's canonicalization was insufficient, and it would have broken every bundle.** The ruling as first written ("UTF-8, lexicographically sorted keys, no insignificant whitespace, `integrity` omitted") reads complete and is not: it pins **key ordering** but says nothing about **string escaping** or **number formatting**, and Python and JavaScript disagree on both by default. Reproduced by execution 2026-08-07:

  ```
  PY  json.dumps(o, sort_keys=True, separators=(",",":"))
      {"attribution":"\u00a9 OpenStreetMap contributors","bbox":[28.0,36.0,28.5,36.5]}
  JS  JSON.stringify(o)
      {"attribution":"© OpenStreetMap contributors","bbox":[28,36,28.5,36.5]}
  ```

  `json.dumps` defaults to `ensure_ascii=True` and escapes the `©` that **every** manifest carries in its ODbL attribution — that half is constant and universal. The number half is **intermittent**, and an earlier version of this amendment overstated it: Python renders `28.0` where JavaScript renders `28`, but *only for integral-valued floats*, so a real Rhodes bbox `[28.216, 36.44, …]` serializes identically and only a bound landing on a whole degree diverges. **The intermittency makes it the worse of the two** — a digest that mismatches for some areas and not others reads like corruption rather than a serialization bug. Either way the writer (Python, T040) and the launch-time verifier (TypeScript, T053) compute different digests and the bundle fails its own integrity check — **offline, on the device, undiagnosable**.

  **Pinned: [RFC 8785 (JSON Canonicalization Scheme)](https://www.rfc-editor.org/rfc/rfc8785)**, which fixes escaping and number formatting as well as ordering, with verified implementations on both sides (`rfc8785` on PyPI, `canonicalize` on npm, both resolved-then-pinned per ADR-0007). Hand-rolling either side re-opens the gap. `itinerary_hash` (ADR-0023) inherits the same rule — it is SHA-256 over "the canonical `ItineraryV1` JSON" and has exactly the same two failure modes.

  *Found by a parallel session's review and verified here by execution rather than accepted. It is the best argument in this ADR for naming a standard instead of describing one: the description looked complete to two independent readers and was wrong.*

- **A4 — ruling 8's asymmetry is accepted, but named as debt.** Deriving bundleability for `Story` instead of reading a stamp leaves the quarantine filter's logic duplicated in one place — the "per-source vigilance" that ADR-0009's stamp-at-the-boundary pattern exists to eliminate. Adding `observed_at` (ruling 8) arguably makes `Story` *more* `SourcedValue`-shaped without being one, which makes the trap subtler rather than clearer. Documenting it stays the cheap call for M1; **if a `SiteRecordV2` is ever opened, promoting `Story` to a `SourcedValue` should be the first thing folded in.**
