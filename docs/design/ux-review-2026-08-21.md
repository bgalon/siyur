# UX review + fix plan — driving the app after DU-06b

- **Date:** 2026-08-21 · **Status:** proposed, for Ben
- **Method:** the running app driven through every flow at **500 × 667**, against a live stack
  (real PostGIS, real Overture/OSM data, a real model call). Measured in the page, not eyeballed.
- **Supersedes nothing.** `ux-audit-2026-08-15.md` measured *screens* and DU-06b fixed them; this
  reviews the *product* now that the screens work.

## Why this exists

DU-06a's gate is green, DU-06b landed the phone layout, and the journey completes at 390 px
(`media/du06b-journey-390px.gif`). All of that is true and none of it makes the product good.
This review is the next bar: **can a person who is not us use it, and does it look like something
we would ship.**

**One viewport caveat, stated up front.** Chrome on macOS refuses windows below ~400 px, so this
pass was driven at **500 px**. Every finding below is width-independent *except* the control-row
alignment (R-19), which needs re-checking at a true 390 — the DU-06a Playwright gate can do it.

### The front door

| id | sev | finding |

| **R-01** | **B** | **A name search takes 65 s and then says nothing at all.** The server answers `404` with its candidates; the client renders no chooser, no error, no message — the screen returns to its initial state. - **The coverage card's copy is the best writing in the product**: *"883 cited places already in the

## 2. Decisions that are Ben's

### D-1 · How much attribution does the obligation actually require? · blocks R-05

**This is the expensive one and the only one that needs an ADR.** ADR-0019 mandates per-value
provenance and the tests assert chip/value co-presence; Constitution Article V sits behind it.
Moving to per-source attribution is not a CSS change — it reopens a ratified decision.

| option | cost | note |
|---|---|---|
| **a** keep per-value | 0 | the day stays unreadable |
| **b** per **stop**: one "Sources: …" line per stop | 1.5 d + ADR | **recommended** — same licences named, 21 chips → ~6 lines |
| **c** per **view**: one line per rendered day | 1.0 d + ADR | cheapest; weakest link between a value and its source |
| **d** chip on hover/expand, source line always visible | 2.5 d + ADR | best of both, most work, new interaction on a phone |

### D-2 · What names an area? · blocks R-08

`Area.name` is null for map-drawn areas. The work is ~1 d; the question is the decision.
Reverse-geocode the centroid (a network call and a new failure mode)? Name it after the first
stop (only exists after planning)? Ask the user at delimit time (one more field on a screen with
no room)? **Recommend: the user may name it, defaulting to a reverse-geocoded suggestion, with
the bbox as the last resort** — but this is genuinely yours.

### D-3 · Does the default budget move, or does the planner fit it? · blocks R-03

Three coherent answers: raise the default to ~6 h; have the planner treat the budget as a
constraint it must satisfy rather than a target it may exceed; or keep both and make R-04's
in-place fix the answer. **Any one works. The current combination is the only one that cannot.**

### D-4 · Are uppercase mono field labels "chips"? · blocks R-20

Recommendation from the DU-06a session, unchanged: **raise the six form labels to 14 px** (they
are the instruction, not metadata about a value — measured: no overflow or clipping regression at
any width), and **keep the ODbL credit at 12 px with its own named exemption**, as
`INLINE_TEXT_TARGETS` was done for tap size.

## 5. Definition of done

Deliberately not "the tests pass" — that phrase is what produced the 2026-08-15 audit, and R-01 is
what it produced next.

1. **A name search that cannot resolve shows the user the candidates**, verified against the
   **running API**, not a fixture.
2. **No guardrail in this plan asserts a shape it invented.** Where a test doubles the API, the
   doubled shape is asserted against the real one at least once.
3. Each finding maps to a closed task or an explicit deferral with a reason.
4. **A person completes the first-run journey accepting the defaults** — delimit, plan, approve —
   without editing a number to make it work (Wave C).
5. The DU-06a gate stays green, and **any `KNOWN_RED` row a fix flips is deleted in the same PR**.

## Appendix A — the measurement harness

Every number in §1 came from these probes, run in Claude-in-Chrome against a live stack. They are
here so the **re-review is a diff, not a fresh opinion**: run them again after a change and
compare to the baseline column. A finding is closed when its number moves, not when someone says
it feels better.

**Setup.** Start a stack on your own ports, open the app, paste the dev cookie

const ratio = (a,b) => { const l1=lum(a), l2=lum(b); const [hi,lo]=[Math.max(l1,l2),Math.min(l1,l2)]; return Math.round(((hi+0.05)/(lo+0.05))*100)/100; };
