## 2. Phase C — do this next

It is the audit's **F-08, F-09, F-10**, ending with **T056**, the airplane-mode gate that
defines M1 as done. T056 now has a real bundle to gate on for the first time.

**F-08 — wire `travel/` into `main.ts`** (~1.5 d). Six modules, 686 lines, already built and
tested. `travel/parse` and `travel/types` are already proven in the live plan path.

**F-09 — wire `bundle/` and build the OPFS URL rewriter** (~2.5–3.5 d). Ten modules exist; the
rewriter does **not**.

> **The load-bearing constraint, and the one most likely to be "fixed" wrongly:** the bundle
> ships **bundle-relative** paths — `glyphs/{fontstack}/{range}.pbf`, `sprites/dark`,
> `pmtiles://tiles/area.pmtiles` — because an offline artifact cannot know its own origin at
> compile time. The client rewrites them to OPFS URLs **at load**. MapLibre requires
> `style.sprite` to be **absolute** (that is FAIL-007), and the absolute form is produced **by
> the rewriter at render time**. Do **not** bake absolute URLs into the bundle; it would stop
> being portable. `compiler/style.py`'s docstring says this at the point where someone would
> otherwise undo it.

This is also the **first contact between the client and a real bundle** — `web/src/bundle/` was
built against a *synthetic* one derived from `docs/data/bundle-manifest.md`. **Treat every
divergence as a finding**: if the client needs changing, the fixture was wrong, which is the
point of deriving it from the card.

**F-10 — close ADR-0031** (~0.5 d). The manifest records `sha256` for `glyphs/` and `sprites/`;
`web/src/bundle/types.ts:54` types glyphs as `{path, license?}` and `manifest.ts` **drops
unknown keys**, so the launch-time integrity check **silently ignores both digests**. ADR-0031
is `accepted` **while half-implemented** — see FAIL-014, which exists because of exactly that.
A hash nothing verifies is a field, not a guarantee.

**Then T056** — grow `web/test/e2e/airplane.spec.ts` into the real gate.

## 3. Things you cannot work out from the code, and will lose time to

**The viewport gate has a countdown built into it.** `web/test/e2e/viewport.spec.ts` marks known
failures with `test.fail()` via a `KNOWN_RED` table keyed per `(assertion, width)`. **Playwright
fails the run when a `test.fail()` test passes.** So the moment your change fixes something, CI
goes red with *"Expected to fail, but passed"* until you delete the matching rows. That is
deliberate — it is what makes the gate a control rather than a snapshot.

**Run the gate first and let it tell you which rows flipped. Do not delete the ones you hope
did.** Doing that caught a real remaining defect: `T-02` at **430** did not flip, because the
control row only wraps under the panel once it runs out of inline space.

**`resize_window` cannot give you a real mobile viewport here.** The page sits at ~50 % zoom, so
`innerWidth` reports 1574 against an `outerWidth` of 767. Use an iframe — media queries respond
to *its* width:

    const f = document.createElement('iframe')
    f.style.cssText = 'width:390px;height:844px;border:0'
    f.src = '/'
    document.body.appendChild(f)
    // then measure inside f.contentDocument / f.contentWindow

**Do not pre-build before a Playwright run.** Its `webServer` builds too; running `pnpm build`
in the same command races over `dist/` and produces bogus failures.

**`strict: true` is on.** Branch protection requires all seven checks *and* an up-to-date
branch, so expect a rebase per merge when two sessions are active. `gh pr update-branch <n>`
does it properly.

**Gate merges with `scripts/merge-guard.sh <pr>`.** Never `gh pr checks | tail` — failures sort
*above* passes (FAIL-009), and the habit transfers to any command that prints a list. Count it,
filter it by predicate, or ask for JSON.

**and** the stale `.osm.pbf` removed from the volume, because the image reuses a PBF already on
disk.

— a live dev stack is there, and that fixture deletes every row in every table (FAIL-011).

**Eight worktrees exist.** Run `git worktree list` before you start;
`spec-002-plan-compile-offline` is **locked** and holds a branch in a way that can block the
primary checkout.

## 5. Concurrency — this is not a solo repo right now

Up to **three sessions** were active simultaneously. It worked because of two habits, both worth
keeping:

1. **Announce what you hold before you start**, and take the complement. FAIL-008 is two
   sessions doing the same task for two hours.
2. **Message the other session rather than assuming.** The single most valuable message of this
   session was one sentence about the `KNOWN_RED` table, which saved an hour of chasing a
   phantom regression.

A worktree isolates **files**. It does not isolate the database, the ports, the Docker volumes
or the routing graph (FAIL-011).

## 6. Decisions in force

- **Sign-in stays the dev cookie** until the local version functions — sequenced *after* Phase C.
  **Consequence to keep visible:** until then the only way in is pasting `document.cookie` into
  devtools, so every usability claim before that point is about a session a developer started.
- **Phase D (edit a plan) is out of M1.** `supersede_plan` stays implemented and unreachable —
  tolerable *because it is written down*.
- **RTL is out of M1.** Delivery plan says M3, Ben said M2 — unsettled, and it does not matter
  yet: the audit found **zero physical direction properties against 35 logical ones**, so the
  debt is not accumulating. Keep using logical properties.
- **Unknown opening hours warn, they do not block** (ADR-0022 A12). Accepted cost: a traveller
  can approve a day containing places that may be shut, which is why every warning is per stop
  and visible.
- **Below 760 px the app is one scroll column** (ADR-0035, accepted).
- **The ODbL link is exempt from the 44 px floor** under WCAG 2.5.5's inline case — size only;
  it must still be reachable, unclipped and unoccluded.

**Unratified:** ADR-0028 (deferred by design until M1 lands) and **ADR-0034** (`proposed` — a
stop snaps to the network that serves the day). 0034 wants Ben.

## 8. The pattern this repo keeps finding

Worth reading before writing any new check, because it has now appeared **seven times under
four names**:

**A control that looks active and isn't** — a truncated `check_id` suppressing nothing; a
devlog-debt hook matching filenames; `gh pr checks | tail` hiding failures that sort first; a
guard against green-for-the-wrong-reason that was itself green for the wrong reason.

**A control that works perfectly and admits nothing** — the HITL gate was unreachable in
practice because no real day could satisfy `feasible IS TRUE`, with every test around it green;
`DisconnectedWalkGraphError` refused every real area because stops snapped to their nearest edge
blind to connectivity.

**A truthful field rendered as the answer to a question it wasn't asked** — the coverage card
denying 958 places; `data-plan-state="proposing"` beside "No day has been proposed yet";
`researched_at` null on researched ground.

**The artifact under test was not the artifact that ships** — FAIL-015: a fix correct in dev and
broken in `dist/`, because a media query adds no specificity and the bundler concatenates in
import order. Every source-level check passed throughout.

> The common factor, and the sentence to keep: **each control was verified against the path it
> was written for, and never against the path it would actually meet.**
